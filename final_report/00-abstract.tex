\begin{abstract}
We built a working multi-tenant identity and authorization platform for a learning SaaS. One person can belong to several organizations with a different role in each, and a role in one organization never leaks into another. Authentication is delegated to Keycloak~26.8.0 with the OAuth~2.0 authorization-code flow and S256 PKCE. Everything identity providers usually leave to the application is ours: global user mapping keyed by issuer and subject, tenant memberships, resource ownership, relationship rules, Casbin-based authorization with deny-overrides, idempotent tenant provisioning with per-tenant SSO association, purpose-specific consent and transactional audit. The backend is a modular monolith (Node.js~24, Fastify~5, PostgreSQL~16) started with one Docker Compose command.

Programs are first-class principals. A reporting agent (AG01) runs as an application service principal with exactly one action in one tenant. In the final week we finished the extension promised in our Week~1 design: an assistant agent (AG02) that can act for a user only through a revocable delegation bound to one tenant, a list of scopes and an expiry, with permission equal to the user's \emph{current} permission $\cap$ the delegated scope $\cap$ the tenant.

From a fresh clone of the final revision with new volumes, \textbf{253 of 253} tests pass against real PostgreSQL and a live Keycloak (0 failed, 0 skipped); a mutation runner shows that the tests catch \textbf{15 of 15} deliberately broken security guards and reports a stopped database as inconclusive rather than success; and an 11-step real-browser proof passes on two host names, including a delegation created in the browser and used by the real agent. Revoked sessions and delegations are denied on the very next request (17--174\,ms in our samples).

The report also records, in detail, the 36 mistakes, issues and problems we met: an over-scoped first proposal, integration surprises in Keycloak, a refactor that silently broke consent withdrawal, tests that could not fail, results reported for revisions they did not apply to, a late protocol freeze, and errors made by the AI coding agent we used, together with how each was found and fixed. Native mobile apps, full SCIM, real corporate identity providers and production hardening are documented as limitations rather than claimed.
\end{abstract}
